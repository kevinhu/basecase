# Basecase demo plan — 2:30

## Audience and promise

For researchers who need to move quickly from a biological question to inspectable genomic evidence. The demo should feel calm, grounded, and actionable—not like a generic chatbot pasted beside a genome browser.

## Storyboard

| Time | Picture | Narration beat |
| --- | --- | --- |
| 0:00–0:08 | Clean title card, then the Basecase workspace | Introduce Basecase as an evidence workspace |
| 0:08–0:25 | BRCA1 viewport and track stack | Explain the browser + agent relationship |
| 0:25–0:48 | Ask for hypertrophic-cardiomyopathy genes; show live progress and answer | Disease question becomes ranked, linked loci |
| 0:48–1:05 | Open MYH7 and show the focused locus | Answers are actions, not dead-end prose |
| 1:05–1:24 | Shift-drag two ranges; show focus cards and context chips | Multiple ranges become explicit question context |
| 1:24–1:43 | Ask for rs334 nearby enhancers; show track actions | Arbitrary variant + regulatory-context query |
| 1:43–2:03 | Ask about a VCF row; click exact query anchor | Separate exact allele from surrounding context |
| 2:03–2:20 | Add response annotations as a track; reload and show persistence | Agent can write grounded results back into the browser |
| 2:20–2:30 | Wide workspace and closing title | Summarize the loop: ask, inspect, focus, annotate |

## Capture notes

- Record at 1600×900 and deliver at 1920×1080 H.264 with AAC narration.
- Keep the cursor movement deliberate and avoid unnecessary scrolling.
- Use subtle 4–6% punch-ins only when a precise interaction needs emphasis.
- Let live reasoning remain visible briefly, but never expose private chain-of-thought; show only the product’s summarized reasoning stream.
- Use the app’s native typography and restrained slate palette for title cards.
